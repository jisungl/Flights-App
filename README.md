# Flight Reservation App

A console-based flight booking system built with Java and PostgreSQL. Users can create accounts, search for direct and multi-leg itineraries, book flights with seat capacity enforcement, and pay for reservations from an account balance. Built for CSE 344 (Data Management) at the University of Washington.

**Note:** The project framework (abstract query class, REPL, database connection utilities, and test harness) was provided by the course instructors. All query logic, schema design, authentication, and transaction handling were implemented by me.

## Commands

- `create <username> <password> <initial_balance>` — register a new account with a starting balance
- `login <username> <password>` — log in to an existing account
- `search <origin> <destination> <direct> <day> <count>` — find itineraries sorted by total duration
- `book <itinerary_id>` — reserve an itinerary from the most recent search
- `pay <reservation_id>` — pay for an unpaid reservation from account balance
- `reservations` — view all reservations and their payment status

## Schema

Three custom tables support the booking system on top of the provided `Flights`, `Carriers`, `Aircraft_Types`, and `N_Numbers` tables:

- **Users** — username, salted/hashed password (BYTEA), account balance
- **Itineraries** — day, total price, total duration, number of flights, and foreign keys to one or two flights
- **Reservations** — reservation ID, payment status, and foreign keys to the user and itinerary

## Implementation Details

**Search** queries for direct flights first, using parameterized SQL with multi-table joins across `Flights`, `N_Numbers`, and `Aircraft_Types` to retrieve seat capacity alongside flight details. If indirect flights are allowed and the direct result count is below the requested limit, a second query finds two-hop itineraries by joining `Flights` to itself on matching stopover cities and dates. Results are sorted by total duration, then by flight ID.

**Authentication** uses PBKDF2 with HMAC-SHA1 for password hashing. A 16-byte salt is generated per user and stored concatenated with the 128-bit hash in a single BYTEA column. Login extracts the salt, re-hashes the provided password, and compares the result.

**Booking** runs inside a manual transaction (`setAutoCommit(false)`) that checks for same-day conflicts, verifies seat capacity by counting existing reservations against each flight's `num_seats`, inserts the itinerary and reservation atomically, and rolls back on any failure. Reservation and itinerary IDs are generated by querying the current max and incrementing.

**Payment** also runs transactionally — it verifies the reservation exists, is unpaid, and belongs to the logged-in user, checks sufficient balance, then atomically deducts the price and marks the reservation as paid.

- Java

## Usage

Start the SSH tunnel to the database:
```bash
./pgtunnel.sh
```

Compile and run:
```bash
mvn compile exec:java
```
